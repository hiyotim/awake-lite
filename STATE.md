### R3a/R3b reliability units (2026-11-08, live check 2026-11-09)

**R3a owner liveness.** `Sources/Adapters/OwnerIdentity.swift` gained an injectable `OwnerLiveness` seam (`system()` in production, `evaluate(...)` for tests). An owner is dead only when: its boot token differs from the current boot; `pid <= 1`; `kill(pid, 0)` returns `-1` with `ESRCH`; or a measured owner's fresh `OwnerIdentityProbe.measure` disagrees on pid, uid, start time, or boot token. A supplied owner (`startTimeMicros 0`) is dead only on provable PID absence; `EPERM` and any indeterminate result are not dead. `ActivityModel.activeOwners` and `retireOwner(_:at:)` now share the `applyOwnerTerminated` freshness rule: a termination never ends work observed later and never moves `updatedAt` backwards. `AppCoordinator.Configuration.ownerLiveness` retires dead owners only on existing reconcile passes while OMP is active; it saves the checkpoint before delivering the decision and reverts the in-memory model if that save fails. Evidence: `OwnerLivenessTests` 9; `AppCoordinatorTests` 12 (3 new: injected liveness, supplied live owner, supplied dead owner); `swift test` 259 tests, 0 failures in 9.243 s; `./build.sh` exit 0; `codesign --verify --strict AwakeLite.app` passed. A live kill of a real OMP process was not run.

**R3b inbox cap.** `StoreError.inboxFull`; `enqueue` enforces `maxInboxFiles` under the existing `.lock` (0.5 s bounded wait, 5 ms retry slice) before creating any file, and `reconcile` waits up to the same bound because producers now share that lock. An inbox at or above the cap records a `storageOverflow` gap for every affected scope and cannot return idle, even after the files drain. The helper maps the refusal to exit 4 with one payload-free line. Evidence: `LocalEventStoreTests` 39 (cap refusal, at-cap overflow gap, reconcile waits for a producer lock; the immediate-contention case still throws `.locked`); `HelperIngestTests` 32 (refused emission returns 4, one line, no new file). Residual: writers that bypass `enqueue` are not counted; a lock held past 0.5 s still fails with `.locked` (exit 4, or a reconcile retried on the next pass); a byte-identical duplicate replay is refused at the cap though no stored fact is lost.

**R3c fix (implemented and live-verified).** `ActivityModel.supersedeStaleMainRuns(family:at:)` ends an active main run (`parentWork == nil`) whose generation is below the maximum generation among main records in the same full `SessionIdentity`, when its `updatedAt <= date`: it sets `.ended`, stamps that one `date`, prunes terminal records, and is idempotent. Child work, other sessions/instances/families, the newest generation, and records updated after `date` are untouched, and the group maximum is taken over main records only, so a child's higher generation cannot end its parent. `AppCoordinator` replaced `retireDeadOwners()` with `settleStaleWork()`: in `reconcileNow()`, after a successful `store.reconcile()` and only while OMP is active, it runs the supersede rule and then the existing liveness-based dead-owner retirement with one `Date()`, saves the checkpoint once if anything changed, and on save failure restores the previous model and reports one Russian diagnostic. The decision is delivered after that settlement, so startup collapses a persisted orphan on the first pass; a live owner is still never retired. The bundled asset's `session_start` handler now reports `run_superseded` for an active `runGeneration` before resetting it, so the normal path no longer orphans a run; the installed copy under `~/.omp` stays old until a future reinstall, and the model-side rule protects the currently installed extension. ## Remaining known limits

- Removal and reinstall protections (receipts, journals, generation checks, hash-checked rollback) are retained and fixture-tested, and now driven at startup.
- A supplied owner is separated by its per-process token but carries `startTimeMicros 0`; a liveness probe cannot confirm that a live pid still names the recorded owner and must stay conservative.
- The extension ignores helper exit codes by contract, so inactive, stale, or failed emissions are invisible to OMP; only missing events reveal them.
- `session_switch` cannot retire an old OMP session authoritatively because it names no old-session identifier.
- `agent_end` carries no outcome; a terminal `agent_end` or `session_stop` completes the run. Failures and aborts also settle as completed.
- Process presence, silence, and low CPU remain invalid activity evidence.
